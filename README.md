# ガイセンNOW 稼働状況

公開URL: https://gaisen.1mr.jp/status

本体と配信元を分離した，日本語のステータスページです．監視対象は「ガイセンNOW」1件のみです．

## 構成

- Cloudflare Workers の Cron Trigger で約5分ごとにトップページ https://gaisen.1mr.jp/ を確認します．HTTP 200 と本文の「ガイセンNOW」を確認し，失敗時は最大3回試行します．
- 実測した接続状態，応答番号・時間，障害の発生と復旧，観測済みの時間区間を Workers KV に保存します．閲覧されていない間も実行・保存します．
- `/status/data.json` は保存済みの記録から公開用の状態・稼働率・履歴を返します．GitHub Actions の定期実行を画面更新の前提にしません．
- GitHub Actions は履歴のバックアップ専用です．約1時間ごと，または手動実行で 監視側の公開URL `https://gaisen-status.1mr.workers.dev/status/history.json` を取得し，`history/cloudflare-state.json` と `status-data.json` を保存します．この処理の遅延は公開画面の監視・履歴更新に影響しません．
- GitHub の `maintenance` ラベル付き Issue は，監視処理が約1時間ごとに取得します．新しい障害のお知らせは定期監視が直接作成・更新します．
- GitHub Pages は `docs` を画面変更時だけ配信します．Cloudflare Worker が画面・ロゴ・フォントを取得し，本体を経由せず `/status` を配信します．
- ロゴ，LINE Seed JP，配色，ヘッダー・フッターは本体と統一しています．ニュースページの個別監視は行いません．

## 無料枠

Workers は Free プランのままです．5分ごとの定期監視は1日288回で，KVへの書き込みも通常1日288回です．KVの無料枠は読み取り10万回/日，書き込み1,000回/日，保存1GBです．配信時は結果を最大60秒キャッシュし，書き込みを行いません．有料プランへ自動変更しません．

処理は観測済み区間の境界を維持したまま，同じ状態が連続する区間だけをまとめて保存します．稼働率の計算を軽くし，無料枠のCPU制限内で動かします．

## 記録と表示

- 接続先，監視結果，GitHubへの保存，画面表示は「ガイセンNOW」1件です．
- 稼働率は実際に観測できた時間で重み付けします．初回測定だけでは稼働率を作りません．15分を超えて確認が空いた区間は不明として集計から除外します．
- 日別履歴は日本時間です．計測なしは灰色，正常は緑，障害は赤，応答遅延は黄で表示します．日時の境界で観測時間を正確に分割します．
- HTTP 200 でも本文の確認に失敗すれば障害として扱います．接続と本文の確認であり，個別ページや全機能の動作を網羅するものではありません．
- 障害中に複数の番号が出た場合は同じお知らせに保存します．復旧後の HTTP 200 で検知時の番号を上書きしません．応答なしは「HTTP応答なし」，番号不明は「エラー番号の記録なし」です．
- UptimeRobot 独自の `333333` などは「監視エラー」と表示し，HTTP番号と区別します．番号から原因を推測しません．
- 画面は約60秒ごとに保存済みの結果を取得します．定期監視の結果が10分以上古い場合だけ，配信元から現在の接続を追加確認し，履歴側の更新日時を明記します．この追加確認で履歴や空白区間を作り足しません．
- 最終確認が20分以上古く，現在の接続確認も取得できない場合は，最新の状態を確認できていない旨を表示します．

## 過去履歴と切り替え

UptimeRobot の監視800442063から2026年11月15日に一度だけ取得した原本と正規化した履歴を `history/imported` に保持しています．以後，UptimeRobotへ継続接続しません．旧監視は停止済みです．

- 26件の障害・復旧時刻を保持しています（最古は8月9日）．日別稼働率は8月18日〜11月15日の90日分です．
- 元の日別集計はUTCです．正確な発生・復旧時刻から計算した90日すべてのUTC日別稼働率が，元の数値と0.001ポイント以内で一致することを確認し，日本時間で再構成しています．
- 統計上の引き継ぎ範囲は2026年8月18日09:00〜11月15日22:43:24.977（日本時間）です．以降の実測結果との重複は二重計上しません．元の各チェックの回数は取得できないため作り足しません．
- 元の公開レスポンスとSHA-256を保持しています．当時の汎用エラー説明を障害原因として表示しません．

2026年11月16日に旧ページ別監視を単一のトップページ監視へ移し，同じ接続先の開始日時と実測結果を継承しました．旧チェック台帳・結果・概要は `history/retired/20261116-single-monitor` に原本を保存しています．重複していたGitHub Issueは重複扱いに整理し，元の証拠は削除していません．

同日，GitHubの定期実行の遅延を避けるため，監視と履歴保存をCloudflareへ移しました．`history/cloudflare-seed.json` が切り替え前の観測区間・日別件数・お知らせの初期記録です．元の全実測結果と日別・期間別の集計がミリ秒の記録精度で一致することを検証しています．切り替え時の15分を超える未観測区間も補完しません．

## 運用と復旧

- Cloudflare の `gaisen-status` に `STATUS_STORE` を接続し，`gaisen-status-history` 名前空間を使用します．Cronは `*/5 * * * *` です．設定は `wrangler.jsonc` に保存しています．
- `node scripts/build-worker.mjs` で，ダッシュボード編集用の単一ファイル `dist/worker.js` を生成します．認証済みのWranglerなら `src/worker.js` を直接デプロイできます．
- コード公開後は `STATUS_STORE` の接続と `*/5 * * * *` のCronを確認します．ダッシュボードのCron追加ダイアログを閉じた後，ページ下部の「保存」を押して未保存の変更が消えるまで待ちます．ページを読み直しても設定が残ることを確認してから，本番の定期実行が複数回成功し，公開データの確認時刻と履歴が進むことを確認します．
- GitHubのバックアップは Actions の「監視履歴をGitHubに保存」から手動実行できます．公開可能な監視記録だけを保存します．
- 保存先を復旧する場合は `history/cloudflare-state.json` の最新バックアップをKVの `state` に戻します．保存データがない時は監視処理が最新のGitHubバックアップ，なければ初期記録を読みます．取り込めない場合は失敗として扱います．
- 画面変更は `docs` を更新してmainへpushします．即時反映が必要ならWorkerのキャッシュキーも更新して再デプロイします．
- Workerのルートは `gaisen.1mr.jp/status*` です．画面に必要な許可済みリソースと，公開用の監視結果・履歴だけを配信します．任意のURLは取得できません．公開エンドポイントから監視記録を書き換えることはできません．
- 従来のUpptimeスクリプトと実測結果は移行の検証用に保持しています．通常の監視では実行しません．
