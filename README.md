# ガイセン NOW 稼働状況

公開 URL: https://gaisen.1mr.jp/status

本体と配信元を分離した、日本語のステータスページです。

## 構成

- GitHub Actions の標準 Linux ランナーで、Upptime v1.46.5 を約 5 分ごとに実行。
- 監視は「ガイセンNOW」1件のみ。トップページ https://gaisen.1mr.jp/ の HTTP 200 と本文の「ガイセンNOW」を確認。ニュースページへの個別監視は行いません。
- Upptime が接続障害の Issue を作成し、復旧時に閉じます。検知時は再試行します。
- `scripts/export-status.mjs` が監視結果と Issue から `status-data.json` を生成。直近 91 日の測定結果を `history/checks.json` に保持します。
- GitHub Pages は専用の公開ワークフローで `docs` を配信。画面変更時だけ実行し、監視データの更新時は再公開しません。
- Cloudflare Worker が `/status` と関連リソースを配信。画面・フォントは GitHub Pages、監視結果は公開リポジトリから取得。本体の Raspberry Pi への接続は不要です。
- 本体と同じロゴ、LINE Seed JP、配色、ヘッダーとフッターを使用。必要なアセットをこのリポジトリ内に保持します。

## 無料枠

このリポジトリは public で、標準ランナーと GitHub Pages を使用します。Cloudflare Workers は Free プランで運用し、有料ストレージや外部 API は使用しません。Worker のリクエスト数はアカウント共通で 1 日 100,000 回まで。上限到達時は停止し、有料プランには自動変更しません。

GitHub Actions の定期実行は混雑時に遅延・欠落する場合があります。最終確認が 20 分を超えた結果は「最新の状態を確認できていません」と表示します。

## 集計と表示

- 稼働率は測定結果間の時間で重み付け。監視開始前と、15 分を超える測定間隔は除外します。初回測定時は「集計中」です。
- 日別履歴は日本時間。データのない日は灰色、計測範囲内で正常なら緑、障害検知があれば赤で表示。
- 通信失敗や不正なデータを正常扱いしません。Worker が前回結果を返す場合も、元の確認日時を保持します。
- 監視画面は 60 秒ごとに表示を更新。閲覧によって監視処理を実行することはありません。

## 運用

- 手動確認: Actions の「ガイセン NOW 稼働監視」から Run workflow。
- 障害の詳細: Upptime が生成する Issue に運用メモを残せます。
- メンテナンスのお知らせ: このリポジトリに Issue を作成し `maintenance` ラベルを付けると、タイトルと状態を公開画面に表示します。公開してよい内容のみを記入してください。
- 画面変更: `docs` を更新して main へ push。GitHub Pages の反映後、Worker のキャッシュは最大 1 時間で更新。即時反映が必要な場合は `src/worker.js` のキャッシュキーのバージョンを更新し再デプロイします。
- Worker 変更: `src/worker.js` を更新し、Cloudflare ダッシュボードのコード編集または認証済みの Wrangler でデプロイ。
- ルート: `gaisen.1mr.jp/status*`。Worker 内で許可したファイルのみを配信します。
- 切り戻し: Cloudflare で `gaisen-status` のルートを削除し、本体のフッターリンクを以前の UptimeRobot の URL へ戻します。UptimeRobot の旧監視は停止済みのため、切り戻す場合は明示的に再開します。

## UptimeRobot の過去履歴

2026 年 11 月 15 日に公開ステータスページから一度だけ取得した履歴を、`history/imported` に保存しています。以後の表示と集計は保存済みデータを使い、UptimeRobot へ継続接続しません。

- 日別集計は 2026 年 8 月 18 日〜11 月 15 日の 90 日分。26 件の障害と復旧の時刻を保存（最古は 8 月 9 日）。90 日より前の期間全体の稼働率は推定しません。
- 元の日別集計は UTC 日付、イベント表示は日本時間です。正確な発生・復旧時刻による UTC 日別の計算値が 90 日すべてで元の数値と一致することを確認してから、日本時間で日別履歴を再構成しています。
- 統計上の引き継ぎ範囲は 8 月 18 日 09:00〜11 月 15 日 22:43:24.977（日本時間）。それ以降は新しい監視の結果を使います。重複する測定区間は二重計上しません。
- 過去の各チェックの回数は取得できないため、5 分ごとの測定点や回数を作り足しません。取り込み前後を通じて単一サービスの履歴として保持します。
- 元の公開レスポンスと SHA-256 も保存し、照合可能にしています。HTTP 530 の説明など、元サービスの汎用エラー説明は推測で障害原因として表示しません。
- `scripts/import-uptimerobot.mjs` は保存済み公開 JSON を読み込む一回限りの取り込み用です。通常の監視ワークフローでは実行しません。

## 単一サービスの監視

設定・監視・GitHub の障害 Issue・公開データ・画面はすべて「ガイセンNOW」1件です。接続先はトップページ、識別子は `gaisen-now`。稼働率はこの一つの実測結果から算出し、ページ別の結果や集約処理は使用しません。HTTP 200 でも本文の確認に失敗すれば障害、応答時間が基準を超えれば応答遅延として扱います。

2026 年 11 月 16 日の切り替え時に、同じトップページを測定していた旧 `website` の開始日時と全サンプルをそのまま引き継ぎます。`scripts/migrate-single-monitor.mjs` は各監視実行前に確認し、初回だけ移行します。旧チェック台帳・監視結果・概要は `history/retired/20261116-single-monitor` に原本を保存し、稼働率や現在の監視には使いません。UptimeRobot の履歴と原本も保持します。

`status-data.json` の `service` が単一サービスの結果です。既存の画面との互換性のため `services` にも同じ1件を収録します。旧ニュース監視の重複 Issue は重複記録として残し、`status` の対象から外します。旧記録の重複を読み込んだ場合だけ、時間帯が重なる記録を一つにまとめます。

## HTTP 応答番号

- サービス欄に最終確認時の応答、お知らせに障害検知時の応答を表示します。復旧後の HTTP 200 で過去のエラー番号を上書きしません。
- 新しい障害の番号は Upptime Issue 本文の `HTTP code:` 行から取得します。過去の UptimeRobot 記録では保存済みの番号を使用します。`333333` などの独自番号は「監視エラー」と表示し、HTTP番号と区別します。
- HTTP 530 などの実際の番号だけを表示し、原因を推測しません。HTTP 応答を得られない `0` は「HTTP応答なし」、番号不明は「エラー番号の記録なし」と表示します。
- 監視の設定は接続と本文の確認です。トップページ以外の個別ページや全機能の障害を網羅するものではありません。
